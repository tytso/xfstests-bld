# fstests-bld

This directory contains the build system for xfstests (the primary
filesystem test suite for Linux) and its various dependencies,
culminating in the creation of `xfstests.tar.gz`.

## Directory Structure & Components

### Build Scripts

*   `get-all`:
    Clones or updates the external git repositories configured in
    `config`/`config.custom`.
	
*   `build-all`:
    Configures, compiles, and installs all subcomponents (both required
    and optional) into the local `bld/` directory.
	
*   `gen-tarball`:
    Packages the compiled tools, libraries, `xfstests` files, and
    `blktests` into the final `xfstests.tar.gz` archive. Can create
    architecture-specific names with `--arch <arch>`. 
	
*   `get-versions`:
    Gathers and outputs the current version/commit information for all
    component git repositories. 

*   `update-all`:
    A simpler script for rebuilding and updating dependencies without
    checking out new commits. 

### Build Targets & Dependencies

These repositories are cloned on-demand into this directory by `get-all`:
*   `xfstests-dev`: The main test suite source.
*   `xfsprogs-dev`: Userspace XFS tools.
*   `fio`: Flexible I/O tester benchmark.
*   `libaio`: Asynchronous I/O library.
*   `quota`: Disk quota tools.
*   `fsverity`: Tooling for managing fs-verity.
*   `blktests`: Block layer testing framework.
*   `android-compat` (in-tree): Compatibility shim when compiling for Android.
*   `dbench` (in-tree): File system benchmark tool.
*   `e2fsprogs-libs` (in-tree): Libraries for ext2/ext3/ext4 filesystems.
*   `libinih` (in-tree): INI parser for xfsprogs.
*   `misc` (in-tree): VM helper utilities.
*   `popt` (in-tree): Option parsing library.

*Optional dependencies* (can be enabled via `config.custom` / uncommented URLs):
*   `ima-evm-utils`: IMA/EVM security tools.
*   `keyutils`: Key management utilities.
*   `stress-ng`: Stress testing tool.
*   `util-linux`: Minimalist util-linux tools.
*   `go/src/github.com/google/syzkaller`: Syzkaller kernel fuzzer components.
*   `nvme-cli`: NVMe command line tools.
*   `ltp-dev`: Linux Test Project.

### Configuration
*   `config`: The default configuration file containing git URLs, default commits, and build variables. Do not edit this file directly.
*   `config.custom`: The user-specific override file. Use this to configure cross-compilation toolchains (`CROSS_COMPILE`, `TOOLCHAIN_DIR`) or enable optional repositories.
*   `config.docker`: Configuration used inside docker-based builds.

### Output Files & Folders
*   `bld/`: The temporary directory where components are installed during compilation.
*   `xfstests/`: The scratch directory where files are organized by `gen-tarball` before archiving.
*   `xfstests.tar.gz`: The output tarball containing the hermetic test suite environment.
*   `xfstests-<arch>.tar.gz` (e.g., `xfstests-amd64.tar.gz`, `xfstests-arm64.tar.gz`): Architecture-specific archives.
*   `*.ver`: Version tracking files for each component repository.

## How to Build
To clean and rebuild everything:
1. Ensure `config.custom` is configured properly (especially for cross-compiling).
2. Enter your build environment (e.g., a chroot).
3. Run:
   ```bash
   make clean
   make
   make tarball
   ```
   Or clean-and-rebuild in one step:
   ```bash
   make all-clean-first
   make tarball
   ```
